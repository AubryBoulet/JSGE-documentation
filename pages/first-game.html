My first game with JSGE

Let’s build a block breaker step by step: a paddle that follows the mouse, a ball, and blocks to destroy.

The complete game, with impact particles and an animated score, is available in the exemples/brick break folder of the repository. This page presents a simplified version that you can edit live at the bottom.

1. The HTML page

You need a <canvas> and a script loaded as an ES module.


<canvas id="gameCanvas" width="1000" height="600"></canvas>
<script src="index.js" type="module"></script>

2. Import the engine and create a camera

The Camera is the “window” onto your game: it receives the canvas element, its dimensions, and a background color (or image). Its target framerate is 60 FPS by default (use camera.targetFPS to change it).


import { Camera, Sprite, Scene, Entity } from "https://cdn.jsdelivr.net/gh/AubryBoulet/JSGE@main/JSGE/jsge.js";

const canvas = document.querySelector("#gameCanvas");
const cam = new Camera({
  canvas: canvas,
  position: { x: 0, y: 0 },
  dimensions: { width: 1000, height: 600 },
  backgroundColor: "black"
});

The canvas parameter is the canvas element itself, not its id.

3. Create sprites

Sprite.create(width, height) builds an empty sprite with its own 2D context, available as sprite.ctx. You draw on it with the usual Canvas methods, without any external image.


const blockSprite = Sprite.create(50, 20);
blockSprite.ctx.fillStyle = "royalblue";
blockSprite.ctx.fillRect(1, 1, 49, 19);   // leave a 1-pixel border

const ballSprite = Sprite.create(10, 10);
ballSprite.ctx.fillStyle = "white";
ballSprite.ctx.arc(5, 5, 5, 0, 2 * Math.PI);
ballSprite.ctx.fill();

To load a real image, use await Sprite.load("path/image.png").

4. Create entities

An Entity pairs a sprite with a position. With physic: true it detects collisions. Entity.create(data, [objects]) also lets you attach your own properties and methods to it (hit points, damage…).


const ball   = Entity.create({ sprite: ballSprite,   position: { x: 495, y: 550 }, physic: true });
const paddle = Entity.create({ sprite: paddleSprite, position: { x: 450, y: 560 } });

5. Group everything in a scene

A Scene keeps its elements sorted by zOrder (0 by default; higher values are drawn on top). The sort is only recomputed when needed, which performs better than drawing entities directly.


const scene = new Scene();
scene.addArray(blocks);   // an array of entities
scene.add(ball);
scene.add(paddle);
// scene.add(elem, 1) to draw on top; scene.remove(elem) to remove

6. Handle collisions

Collisions are declared from the “active” entity. The callback receives the entity that was hit. (Note the spelling of the API: addColision…, with a single “l”.)


ball.addColisionWithArrayOfEntities(blocks, (block) => {
  scene.remove(block);                    // the block disappears
  ball.removeColisionWithEntity(block);   // and no longer counts for collisions
  ball.velocity.y *= -1;                  // bounce
});
ball.addColisionWithEntity(paddle, () => { ball.velocity.y *= -1; });

7. Game logic with onUpdate

camera.onUpdate is called on every new frame, just before drawing: it’s the ideal place for game logic. camera.cameraMousePosition gives the mouse position relative to the camera.


cam.onUpdate = () => {
  const mouseX = cam.cameraMousePosition.x;
  paddle.position.x += (mouseX - (paddle.position.x + 50)) * 0.05;   // smooth movement (lerp)
  // … wall bounces, lost ball, etc.
};

8. The main loop

Three calls, always in this order: clear() starts a new frame, scene.draw(cam) prepares the draw list, and flipBuffer() renders it. Nothing is displayed without flipBuffer(). The engine respects the camera’s target FPS even if requestAnimationFrame fires more often.


function mainLoop() {
  cam.clear();
  scene.draw(cam);
  cam.flipBuffer();
  requestAnimationFrame(mainLoop);
}
mainLoop();

The game, live

Move the mouse to control the paddle and click inside the game to launch the ball. The code is editable: change the speed, the number of block rows, the colors…

Going further

The complete example game also adds:

  • multicolored blocks with hit points, attached to entities through the second parameter of Entity.create;
  • particle emitters (ParticleEmitter) for impacts and destructions. Particle colors must be given as hex or RGB, not as names like “blue”;
  • an animated score using the Text class, drawn on the camera through camera.postProcess.
