Camera

The camera renders your game onto a canvas. It owns the background, the frame pacing, the draw lists, child cameras, lighting, post-processing and the mouse position.

Creating a camera


import { Camera } from "https://cdn.jsdelivr.net/gh/AubryBoulet/JSGE@main/JSGE/jsge.js";

const cam = new Camera({
  canvas: document.querySelector("#gameCanvas"),
  position: { x: 0, y: 0 },
  dimensions: { width: 1000, height: 600 },
  backgroundColor: "black"
}, 60);   // optional second argument: target FPS
ParameterDefaultDescription
canvas–The canvas element (HTMLCanvasElement) the camera renders to. An error is thrown otherwise.
position{x:0, y:0}Where the camera is drawn on the canvas.
dimensions{width:100, height:100}Size of the camera view.
backgroundColornullAny CSS color. Without a background the camera is transparent.
backgroundImagenullPath or URL of a background image.
2nd argument targetFPS60Frames per second the camera tries to stabilize on.

The frame cycle

Every frame follows the same three steps. clear() starts a new frame (and draws the background), then you queue what to draw, and flipBuffer() renders everything. Nothing is displayed without flipBuffer().


function mainLoop() {
  cam.clear();
  scene.draw(cam);       // queue a scene (or entity.draw(cam))
  cam.flipBuffer();
  requestAnimationFrame(mainLoop);
}
mainLoop();

If less than one frame interval has elapsed since the last frame, clear() does nothing and flipBuffer() skips the rendering, so the target FPS is respected even if requestAnimationFrame fires more often. flipBuffer() returns true when a frame was actually rendered. Inside a rendered frame, the order is: onUpdate, scenes, directly drawn entities (sorted by z-order), child cameras, lights, postProcess, then the result is copied to the canvas.

Methods

MethodDescription
clear()Starts a new frame: clears the canvas and draws the background. Also clears the child cameras.
flipBuffer()Renders the queued elements. Returns true if a frame was rendered.
moveCamera(position, mode = "relative")Moves the camera and its content on the canvas. mode is "relative" (add the offset) or "absolute". It is not a scrolling solution.
drawCameraBorder(color)Draws the outline of the camera, handy to debug a camera layout.
initMaskLightEngine()Enables lighting on this camera and returns the light engine.
Camera.createChildCamera(parent, position, dimensions, backgroundColor, backgroundImage)Static. Creates a camera inside another one and returns it (see below).

Properties and callbacks

NameDescription
position, dimensionsPosition on the canvas and size of the camera.
canvas, ctxThe target canvas and its 2D context.
cameraCanvas, cameraCtxThe camera’s own offscreen canvas and context, where the frame is composed. Use cameraCtx for custom drawing.
backgroundColorBackground color.
backgroundImagePath or URL of the background image.
backgroundImageVelocity{x, y}: pixels the background image moves on each new frame.
backgroundImageLoopBoolean, repeat the image while it moves.
backgroundImageFillStyle"fill" (stretch to the camera) or "imageSize" (keep the image size).

toleranceDeltaMilliseconds of tolerance used to decide a new frame is due (2 by default), to absorb the imprecision of requestAnimationFrame.
onUpdateFunction called on every new frame, just before drawing. The right place for game logic.
postProcessFunction called with the camera after everything is drawn, before the frame reaches the canvas. Anything drawn on cameraCtx there ends up on top of the scene: HUD, filters…
onMouseMouveFunction called with the mouse position when the mouse moves over the camera. (Spelled this way in the engine.)
cameraMousePositionRead-only {x, y}: the last mouse position over the camera, relative to it. It keeps its last value when the mouse leaves the camera, so check isMouseOver first.
isMouseOverRead-only boolean: true while the mouse is over the camera.
Camera.camerasStatic: every camera created so far.

Mouse position. The camera works out the mouse position from the position and the size of the canvas on the page, so it stays correct wherever the canvas is placed, and even if CSS scales it. Use isMouseOver to know whether the mouse is currently over the camera.

Child cameras

Camera.createChildCamera(parent, position, dimensions, backgroundColor, backgroundImage) creates a camera inside a parent camera. Its position is relative to the parent, and it must fit inside it (an error is thrown otherwise). The parent clears its children, and they are rendered with it on every frame, but they never clear the canvas themselves.

A child camera is drawn inside its parent camera’s canvas, after the parent’s own elements and before the lights and postProcess. It therefore covers whatever the parent drew behind it, and anything drawn in the parent’s postProcess ends up on top of it. Child cameras are handy for minimaps, split views, UI panels or parallax layers.

Lighting

Lights are managed by the camera: camera.initMaskLightEngine() returns a light engine bound to that camera. Everything about it is on the Light engine page.
